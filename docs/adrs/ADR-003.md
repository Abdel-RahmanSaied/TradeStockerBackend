# ADR-003: PostgreSQL plus versioned analytical object storage

Status: Accepted design baseline

Date: 2026-10-23

Implementation evidence: **None at bootstrap.**

## Context

TradeStocker must support EGX/US swing and intraday advice, Telegram and a human-only execution boundary. This decision reflects the current plan; repository reconciliation and validation are still required.

## Decision

Use exact operational records in PostgreSQL and source/history objects in S3/Parquet with manifests.

## Tradeoffs

Two storage access patterns require retention and recovery coordination; avoids burdening the ledger with all market ticks.

## Alternatives not selected

Everything in one tick table; treating the event bus as permanent history.

## Implementation and validation

Start with `S02-T02` in the task catalog. Link tests and review evidence before treating this as implemented. Revisit only through an approved new/superseding ADR; never silently rewrite an existing accepted safety boundary.
