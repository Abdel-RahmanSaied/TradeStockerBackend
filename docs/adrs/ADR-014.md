# ADR-014: Separate recommendation, delivery, response and fill states

Status: Accepted design baseline

Date: 2026-10-23

Implementation evidence: **None at bootstrap.**

## Context

TradeStocker must support EGX/US swing and intraday advice, Telegram and a human-only execution boundary. This decision reflects the current plan; repository reconciliation and validation are still required.

## Decision

A recommendation revision, message delivery attempt, human response and actual fill are different records. UNKNOWN external delivery is first-class.

## Tradeoffs

More state handling; avoids false execution and exactly-once assumptions.

## Alternatives not selected

A single status field that turns ACK or Telegram SENT into an execution.

## Implementation and validation

Start with `S05-T03` in the task catalog. Link tests and review evidence before treating this as implemented. Revisit only through an approved new/superseding ADR; never silently rewrite an existing accepted safety boundary.
