## Context and verified facts

- `TradeStockerBackend` is not a Git repository, and no parent folder is one. No `.git` exists anywhere under `/Users/asaied/WorkDir/TradeStocker`.
- The plan proves work with Git commits: SOURCE_OF_TRUTH §4, AGENT_PLAYBOOK §4–§5 and the Definition of Done in QUALITY_GATES. `planctl.py validate` refuses `DONE` without a commit hash. It also refuses `S00-T01` DONE until `repo_observation` has status `VERIFIED` and a `head`.
- All 101 other tasks depend on `S00-T01`, directly or indirectly. So without Git, no task can ever reach `DONE`.
- No task in the catalog creates the repository or chooses a Git host.
- ARCHITECTURE §8 and `S01-T01` ("monorepo skeleton") put `web/` inside `TradeStockerBackend`. On disk there is also an empty sibling folder, `TradeStockerServices/TradeStockerFrontend`.
- `S01-T03` and `S14-T02` plan `.github/workflows/*.yml` files. That assumes GitHub Actions.
- The package installer files sit in the backend root, because the pack was unpacked there.

## Options considered

| Option | Summary | Fit with current docs |
|---|---|---|
| A | One Git repository rooted at `TradeStockerBackend`. Decide the frontend later (before `S13-T01`): `web/` inside this repo, or a separate repo in `TradeStockerFrontend`. | Matches every documented path. No doc edits needed now. |
| B | One repository rooted at `TradeStockerServices`, holding backend and frontend. | One CI and one history. But the root `AGENTS.md`, ARCHITECTURE §8 and the playbook's "repository root" all move one level up. Many doc edits. |
| C | No version control. | Not workable: no task could ever be DONE. Rejected. |

## Decision (proposed)

Option A, if the owner agrees. Suggested owner steps, in order:

1. Decide where the installer leftovers go before the first commit: `install_docs.py`, `test_install_docs.py`, `manifest.json`, `README_INSTALL_AR.md`, `AGENTS.root.fragment.md` and `AGENTS.md.tradestocker-backup-20261022T231037Z-2497c7`. Suggestion: keep them outside the repository. They are package files, not project files.
2. Add a root `.gitignore` with at least `.DS_Store`. `.remember/` already ignores itself. Keep `.claude/settings.json` tracked, because its hook enforces AGENTS.md rule 1.
3. Initialize Git in `TradeStockerBackend`, choose the default branch name, and make one first commit of the reviewed baseline.
4. Choose a Git host before `S01-T03` (CI).
5. A session then records the real root, branch and HEAD in `repo_observation` with status `VERIFIED`. A reviewer can then close `S00-T01` against that commit.

No agent may do steps 1–4 without the owner's explicit approval.

## Tradeoffs and operational cost

- A: smallest change, no doc edits now. If the frontend gets its own repo later, API contracts must be shared across two repos and two CI pipelines.
- B: one place for all code and atomic changes across backend and frontend. But it changes the documented root and needs a reviewed plan update with a CHANGELOG entry.
- Operational cost depends on the Git host chosen in step 4. It is not estimated here.

## Security, human-only and data-rights impact

No invariant changes. The repository must never contain credentials, Telegram tokens, broker statements or unlicensed datasets (see `evidence/README.md`, `SECURITY_AND_OPERATIONS.md` and `S01-T02`). Secret scanning is planned in `S01-T03`.

## Validation and exit criteria

- `git rev-parse --show-toplevel` prints the chosen root, and `git rev-parse HEAD` prints a commit.
- `git status --short` is empty after the first commit, or lists only explained files.
- `python3 docs/tools/planctl.py validate` passes after `repo_observation` is updated.
- Moving to option B later stays easy while the history is short.
