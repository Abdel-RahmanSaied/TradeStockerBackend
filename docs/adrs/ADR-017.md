# ADR-017: Bounded local paper prototype

Status: Proposed for independent review; not a production architecture approval.
Date: 2026-10-23. Scope: owner-authorized S00-T07/T08 increment only.

The owner requested both backend and sibling frontend now while provider, risk, identity, capital and deployment decisions remain unresolved. A usable local workflow can validate engineering without presenting synthetic inputs as live or implying roadmap completion.

The increment uses Go standard HTTP routing, pgx and PostgreSQL. One locked JSONB aggregate atomically records accounts, recommendations, positions, journal, audit, dry-run notifications and request receipts. Migration 001 is repeatable and commits under an advisory lock. React/TypeScript/Vite runs in the explicitly requested sibling frontend repository. An ingestion executable submits only bundled fixtures. Python and HTTP research stubs return INSUFFICIENT_DATA. No Telegram network delivery exists.

This deliberately differs from the production chi/sqlc/goose/relational/NATS/LangGraph baseline. It does not replace those original tasks or approve deployment. The aggregate is unsuitable for sustained production growth or high concurrency: every write serializes and rewrites the whole document (reads, since S00-T09, use a lock-free committed snapshot and write only to commit a due expiry once; see [paper read evidence](../evidence/paper-read-performance.md)), history/receipts grow without retention, and audit is not tamper-proof against database administrators. Production migration/backup/restore, event delivery, assessment provenance and identity need separate implementation and review. Existing installer files stay in place; their original manifest remains historical and must not be regenerated over live project state.

The paper test policy is explicitly unapproved for live use; no production risk values change. Live/actual modes are rejected and all live lanes remain disabled. No broker interfaces or credentials exist. Synthetic assessments never establish real market readiness. Fees are zero-fee test assumptions, not performance evidence. Intraday is blocked pending eligibility validation.

Validation: domain safety tests, HTTP tests, PostgreSQL concurrent reservation/fill/rollback/reconnect tests, browser real-API paper buy/reduction tests, unit/build checks, planning tests and dependency scans. Results and remaining gaps are recorded in the local increment evidence and handoff. Independent implementation review is still required.
