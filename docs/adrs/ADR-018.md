# ADR-018: Durable SEC annual research behind a gated, isolated parser

Status: **Proposed for independent review.** Local prototype design for S07-T07; not a production architecture approval.

Date: 2026-10-23 · Proposed by `claude-code-agent` (session `2026-10-23-development-8da61cee`) · Decision authority: Owner, after independent review.

Supersedes: nothing. Related: S07-T07; ADR-002 (Go authority, Python research), ADR-007 (point-in-time evidence), ADR-017 (local paper prototype); REQ-01, REQ-15.

## Context and verified facts

- The owner approved real requests to `data.sec.gov` with User-Agent contact `abdo.am169@gmail.com` (recorded in the development handoff).
- SEC states its EDGAR APIs need no authentication or API keys, asks automated tools to declare a user agent, limits users to 10 requests per second, and may block IP addresses that send excessive requests. SEC states that access may resume once requests stay below its threshold for 10 minutes. SEC does not document which HTTP status signals a limit.
- SEC submissions encode the CIK as a zero-padded string; companyfacts encode it as a number.
- Each 10-K repeats earlier years as comparatives, so "the latest filing for each year" mixes filings and loses older balance sheets.
- SEC filings are not licensed prices and say nothing about EGX. They cannot resolve D-01 or D-02.

## Options considered

1. Parse in Go. Rejected: the plan assigns financial analysis to Python (ADR-002).
2. A long-running Python service with database access. Rejected: it would widen what Python can touch.
3. **Go owns the queue, the SEC calls and storage; Python is a pure function** run per job. Chosen.

## Decision

- **Queue in PostgreSQL** (`research_jobs`): idempotent creation under an advisory lock, a bounded queue, at most 3 attempts with backoff, a 150 s lease for crash recovery, and attempt fencing (a stale attempt cannot overwrite a newer one). A graceful shutdown re-queues the attempt; an interrupted last attempt fails visibly.
- **One worker leader** across API instances, using a PostgreSQL session advisory lock.
- **SEC provider** in Go: URLs built only from `https://data.sec.gov` plus a validated 10-digit CIK; redirects refused; 16 MiB per source; 1 request per second. 403/429 are treated as an access limit (our classification) and start a **durable SEC-wide 10-minute cooldown**, a conservative use of SEC's 10-minute recovery guidance, not a guaranteed unblock, in `research_provider_state`, which every claim respects across restarts.
- **Originals first:** both source documents are stored with SHA-256 before analysis. Sources and events are append-only through triggers.
- **Parser `sec-annual-v2`** in Python, started with `-I` and a fixed two-variable environment: no database URL, API token or SEC contact. Each fiscal year comes from its own original 10-K. Conflicting values are withheld, periods that end after their filing are rejected, later filings with different values are shown as counter-evidence, and availability uses SEC acceptance time as a proxy (public dissemination can come later).
- **Go output gate:** the stored report must name the requested issuer and the stored source hashes, fit in 1 MiB, and claim no entry, backtest or write authority.

## Tradeoffs and operational cost

Simple to run locally (PostgreSQL plus `python3`; no new services or libraries). Throughput is deliberately low: one job at a time, one SEC request per second. companyfacts is today's snapshot, not an archive, so reports are never certified for historical backtesting. No hosting or data cost: SEC access is free; a production deployment would add its own cost (D-06).

## Security, human-only and data-rights impact

No broker, order or financial-state path exists in research. SEC states that information on sec.gov is public and may be copied or redistributed without its permission; this is not a legal review, and commercial or LLM use still needs the owner's review under D-08. The SEC contact email is kept in the ignored `.env.local`, is never sent to Python, and is never returned by the API.

## Validation and exit criteria

Validated by provider boundary tests, report-gate tests, 27 Python tests on Python 3.9.6, real-PostgreSQL tests for idempotency, retry, cooldown, lease recovery, shutdown and fencing, browser tests (a controlled API double for timing races, plus real-API tests), and a documented real SEC run. Evidence: [SEC research evidence](../evidence/sec-research.md). Exit: replace with the production research architecture (NATS/outbox, LangGraph, archived point-in-time filings) when those tasks are approved.
