## S00-T01 — Inspect the actual repository and reconcile this plan

**Owner role:** Tech Lead · **Priority:** P0 · **Relative size:** M

**Dependencies:** None

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-01`, `REQ-15`

### النطاق

Inspect AGENTS instructions, Git branch/HEAD, dirty files, existing code, docs, CI and sibling services. This package has not inspected the user’s repository. Map proposed paths onto reality without moving or deleting existing work.

### المخرجات المقترحة

- `docs/evidence/repository-inventory.md`
- `docs/sessions/<session-id>.md`
- `docs/state/project_state.json`

### معايير القبول

- Record exact repository root, HEAD, branch and working-tree state in a dated session handoff.
- List existing implementations and conflicts; reuse verified work and create an ADR for material deviations.
- Do not mark implementation tasks complete solely because files or prior chat claims exist.
- Reconcile any existing ADR-011 before assigning or replacing its identifier.

### التحقق والاختبارات

- Capture read-only Git inventory and discovered test commands.
- Run the documentation validator; distinguish baseline tool tests from product tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.

## S00-T03 — Qualify market-data vendors and document licensing

**Owner role:** Data Engineering + Owner · **Priority:** P0 · **Relative size:** L

**Dependencies:** `S00-T01`

**Decisions to review:** `D-01`, `D-02`

**Requirements:** `REQ-02`, `REQ-03`, `REQ-13`

### النطاق

Start US and EGX procurement independently. Request sample payloads, exchange coverage, timestamps, corrections, historical depth, entitlements, retention and non-display/derived-data/LLM-use permissions. Marketing pages are not contracts.

### المخرجات المقترحة

- `docs/DATA_PROVIDER_MATRIX.md`
- `docs/evidence/provider-<name>.md`

### معايير القبول

- Produce one due-diligence record per candidate; label UNKNOWN rather than assume coverage.
- Distinguish consolidated US coverage from a single venue; identify auction, quote/trade conditions and halt support.
- Document EGX intraday history, same-session eligibility support, bid/ask coverage and actual L2 availability.
- Record cost and technical evidence without storing credentials; a missing vendor does not block synthetic core development.

### التحقق والاختبارات

- Parse a legitimately obtained sample or mark the sample gate BLOCKED.
- Verify license scope with written provider evidence before any licensed production use.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S00-T04 — Define account, settlement and market-rule research

**Owner role:** Domain Engineer + Owner · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S00-T02`

**Decisions to review:** `D-03`, `D-08`

**Requirements:** `REQ-06`, `REQ-08`, `REQ-13`

### النطاق

Identify intended brokers and account types, then document how effective-dated exchange and broker rules will be sourced. Do not hard-code today’s rules or assume the same eligibility across EGX and US.

### المخرجات المقترحة

- `docs/evidence/broker-rules-research.md`
- `docs/OPEN_DECISIONS.md`

### معايير القبول

- Define unknown account types and settlement capabilities as explicit activation blockers.
- Identify authoritative sources for sessions, holidays, halts, eligibility, fees and taxes; record verification owner and expiry.
- Determine whether the pilot remains private and whether commercial advisory review is required.
- Specify manual statements/imports or optional read-only account access; never request trading credentials.

### التحقق والاختبارات

- Review one EGX and one US hypothetical account capability matrix without presenting it as verified broker behavior.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S00-T05 — Pin compatible toolchains and estimate workload/cost

**Owner role:** Platform Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S00-T01`, `S00-T02`

**Decisions to review:** `D-05`, `D-06`, `D-07`

**Requirements:** `REQ-01`, `REQ-12`, `REQ-13`

### النطاق

Run a compatibility spike for the chosen Go/Python/PostgreSQL/NATS libraries and migration tooling. Establish a measured load profile and an initial infrastructure/LLM/data budget, not a promised latency or return.

### المخرجات المقترحة

- `docs/evidence/compatibility-matrix.md`
- `docs/evidence/load-and-cost-profile.md`

### معايير القبول

- Choose supported stable versions after checking official documentation; pin modules, uv lockfile and container digests.
- Document symbol count, feed event rate, concurrency, analysis budget and expected retention.
- Select authentication provider and deployment approach through D-05/D-06; no custom token cryptography.
- Record costs as dated estimates with source and currency; no production resources are created without approval.

### التحقق والاختبارات

- Build and connect a disposable Go and Python client to PostgreSQL and JetStream.
- Verify the selected LangGraph checkpointer can persist/resume on the pinned versions.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.
