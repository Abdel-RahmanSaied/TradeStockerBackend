# S01 — أساس المشروع والأمان وCI

## الهدف

Create three runnable deployables and repeatable developer/CI environments before business features.

## S01-T01 — Create reconciled module boundaries and build commands

**Owner role:** Go + Python Engineers · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S00-T01`, `S00-T05`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-01`

### النطاق

Create or adapt the monorepo skeleton. Keep Go business modules inside a single Go module initially; create one Python research package and generated-contract locations.

### المخرجات المقترحة

- `go.mod`
- `cmd/platform-core/`
- `cmd/market-ingestion/`
- `internal/`
- `research/pyproject.toml`
- `Makefile`

### معايير القبول

- Three independent entrypoints exist: platform-core, market-ingestion and research-worker.
- Core domain code has no framework or network dependencies.
- Document build/test commands and supported toolchains.
- Do not create a service per advisory role.

### التحقق والاختبارات

- Build both Go binaries and import the Python package in CI.
- Check dependency direction and no import from Go domain into adapters.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S01-T02 — Create local containers and deterministic fixtures

**Owner role:** Platform Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S01-T01`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-01`, `REQ-12`

### النطاق

Define Compose services for app entrypoints, PostgreSQL and NATS; use synthetic data and an approved local S3 substitute or fixture adapter. Avoid unlicensed datasets in Git.

### المخرجات المقترحة

- `deploy/compose.yaml`
- `fixtures/synthetic/`
- `config/example.env`

### معايير القبول

- One documented command starts dependencies with persistent development volumes and health checks.
- Containers run as non-root where feasible; secrets are supplied outside tracked files.
- Offline fixtures run without provider or LLM credentials.
- Teardown is non-destructive by default; removing volumes is explicit.

### التحقق والاختبارات

- Smoke-test clean startup, shutdown and restart with persisted fixtures.
- Verify no live advisory delivery occurs in development defaults.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.

## S01-T04 — Introduce identity, authorization and service credentials

**Owner role:** Security + Go Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S01-T01`, `S00-T05`

**Decisions to review:** `D-05`

**Requirements:** `REQ-06`, `REQ-12`

### النطاق

Implement the approved identity approach with owner/reviewer/read-only roles and scoped service credentials. The private pilot is one owner, but every financial record is account-scoped.

### المخرجات المقترحة

- `internal/auth/`
- `internal/http/middleware/`
- `deploy/iam/`

### معايير القبول

- Unauthenticated access to portfolio and research administration is denied.
- Issuer/audience/expiry, CSRF or token handling and service-to-service authorization are tested for the chosen auth method.
- DB roles separate core writes, ingestion writes and research writes; no shared superuser.
- Credentials are not available to LLM tools or logs.

### التحقق والاختبارات

- Negative auth tests, cross-account identifier tests and expired-token tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S01-T05 — Add observability and safe worker lifecycle

**Owner role:** Platform + Backend Engineers · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S01-T01`, `S01-T02`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-12`

### النطاق

Instrument startup, health, traces and structured logs; enforce context cancellation, bounded worker pools, retry budgets and graceful shutdown.

### المخرجات المقترحة

- `internal/telemetry/`
- `research/src/telemetry/`
- `docs/evidence/lifecycle-tests.md`

### معايير القبول

- Trace/correlation IDs survive HTTP and NATS boundaries.
- Liveness differs from readiness; dependency outage changes readiness without leaking secrets.
- Logs exclude bot tokens, account secrets and full licensed document content.
- Cancellation drains or requeues work and never loses a financial transaction.

### التحقق والاختبارات

- Kill/restart worker during a synthetic job and inspect its recovery.
- Verify bounded concurrency under a slow-provider fixture.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S01-T06 — Create architecture-level threat and no-execution tests

**Owner role:** Security + Tech Lead · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S01-T03`, `S01-T04`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-06`, `REQ-12`

### النطاق

Establish a maintained threat model and architectural guardrails covering human-only execution, data poisoning, prompt injection, SSRF, credentials and unauthorized goal changes.

### المخرجات المقترحة

- `docs/SECURITY_AND_OPERATIONS.md`
- `tests/security/`
- `tests/architecture/`

### معايير القبول

- No broker order placement/cancel/amend capability exists in API contracts or service permissions.
- Untrusted document fetches have allowlists, size limits and internal-network protection.
- Production-risk settings cannot be changed by agents.
- Negative tests are mandatory gates rather than documentation-only promises.

### التحقق والاختبارات

- Test forbidden broker endpoints, private-network URLs and malicious document instructions.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.
