# S05 — محرك المخاطر ودورة حياة التوصية

**Technical scope:** Deterministic policy kernel and recommendation lifecycle

> ملف مولّد؛ مصدر التعريف `../state/task_catalog.json`. الحالة الفعلية في `../state/project_state.json`، وليست في checkboxes هنا.

## الهدف

Enforce all financial and human-only invariants before a recommendation can become actionable.

## بوابة الخروج

Live and replay use the same risk implementation; stale/unfunded/unauthorized advice is rejected; pausing entries preserves position monitoring.

## S05-T01 — Implement shared policy kernel and versioned risk configs

**Owner role:** Go Domain Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S04-T06`, `S02-T03`

**Decisions to review:** `D-04`

**Requirements:** `REQ-05`, `REQ-06`, `REQ-10`

### النطاق

Create a pure Go policy package plus a batch command usable by Python simulations. Version limits, broker/market rules and rounding semantics.

### المخرجات المقترحة

- `internal/policykernel/`
- `cmd/policy-eval/`
- `contracts/policy/`

### معايير القبول

- No LLM/network access in policy evaluation.
- Missing approved limits fail closed; historical example percentages are not defaults.
- Inputs include portfolio revision, data snapshot, strategy and policy versions.
- Decision returns structured pass/fail reasons and executable-size proposal, not an order.

### التحقق والاختبارات

- Golden vectors compare Go API and batch runner results exactly for monetary outputs.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.

## S05-T03 — Implement immutable recommendation revisions

**Owner role:** Go Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S05-T01`, `S02-T04`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-05`, `REQ-06`, `REQ-07`

### النطاق

Create recommendation revision records with entry range, invalidation, horizon, expiry, evidence and policy results. Keep delivery/response/fills in separate state machines.

### المخرجات المقترحة

- `internal/recommendations/`
- `db/queries/recommendations.sql`

### معايير القبول

- Updating a recommendation appends a revision and explicitly supersedes the old one.
- Watchlist/insufficient-data decisions cannot be rendered as actionable buys.
- Acknowledgment never marks execution; expiry does not close a real position.
- Idempotent candidate/version keys prevent duplicate logical advice.

### التحقق والاختبارات

- State transition, supersession, race and duplicate recommendation tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S05-T04 — Close the research-to-delivery race

**Owner role:** Go Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S05-T02`, `S05-T03`, `S04-T06`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-03`, `REQ-04`, `REQ-05`, `REQ-08`

### النطاق

Revalidate price, account revision, policy, market status and report validity immediately before committing an actionable recommendation and again before delivery where needed.

### المخرجات المقترحة

- `internal/recommendations/finalize/`
- `tests/integration/toctou/`

### معايير القبول

- A material new filing invalidates cached qualifying research.
- Stale price or portfolio changes during committee work force recompute or rejection.
- Final allocation and risk checks occur atomically for account-scoped budgets.
- Expired advice cannot be revived by a delayed worker.

### التحقق والاختبارات

- Concurrent fill during analysis, delayed publish and invalidated-report integration tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S05-T05 — Build entry pause, loss review and degraded-mode behavior

**Owner role:** Go Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S05-T03`, `S05-T04`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-05`, `REQ-06`, `REQ-12`

### النطاق

Implement scoped entry pause/global safe mode with audited human override rules. Keep critical monitoring and exit/reconciliation prompts operating where data permits.

### المخرجات المقترحة

- `internal/safety/`
- `docs/runbooks/entry-pause.md`

### معايير القبول

- Paused entries cannot be bypassed by chief agent, goal engine or Telegram button.
- Existing positions remain tracked and no automatic exit is implied.
- Stale market data is displayed explicitly in risk alerts.
- Resuming entries requires defined checks, authorized approval and a new audit event.

### التحقق والاختبارات

- Provider outage, loss-threshold, paused-entry and unauthorized-resume tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.
