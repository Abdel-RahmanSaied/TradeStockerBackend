## S14-T01 — Provision approved AWS topology with least privilege

**Owner role:** Platform Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S00-T05`, `S13-T06`

**Decisions to review:** `D-06`

**Requirements:** `REQ-12`, `REQ-13`

### النطاق

Provision approved ECS application workers, RDS PostgreSQL, S3 and a durable NATS deployment or approved managed provider via Terraform.

### المخرجات المقترحة

- `deploy/terraform/`
- `docs/evidence/infrastructure-review.md`

### معايير القبول

- Environment/account/network boundaries and resource budgets are explicit.
- No public database or unrestricted NATS endpoints.
- NATS persistence and HA topology match the approved failure model.
- Production provisioning and recurring spend require explicit owner approval.

### التحقق والاختبارات

- Terraform validation/plan review, least-privilege checks and private-network smoke tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S14-T02 — Build provenance-aware CI/CD and release manifests

**Owner role:** Platform Engineer · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S14-T01`, `S01-T03`

**Decisions to review:** No additional decision ID.

**Requirements:** `REQ-12`, `REQ-14`

### النطاق

Build immutable images with pinned dependencies, SBOM/provenance and registry digests; deploy through OIDC-scoped GitHub Actions and approval-protected environments.

### المخرجات المقترحة

- `.github/workflows/release.yml`
- `deploy/releases/`

### معايير القبول

- No long-lived AWS keys in CI and no deployment credentials for untrusted PRs.
- A release identifies code, DB migration, contracts, models/prompts and strategy/policy configs.
- Separate deploy from lane activation.
- Rollback plan documents schema compatibility and does not pretend to reverse economic events.

### التحقق والاختبارات

- Tampered artifact, denied environment and previous-version rollout tests.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.


## S14-T03 — Validate backup restore and disaster recovery

**Owner role:** Platform + QA · **Priority:** P0 · **Relative size:** M

**Dependencies:** `S14-T01`, `S14-T02`

**Decisions to review:** `D-07`

**Requirements:** `REQ-12`, `REQ-14`

### النطاق

Exercise DB point-in-time restore, evidence availability, credentials recovery and NATS consumer reconstruction in a separate environment.

### المخرجات المقترحة

- `docs/runbooks/disaster-recovery.md`
- `docs/evidence/restore-drill.md`

### معايير القبول

- Measure recovery time/data loss against approved RTO/RPO, not merely backup job success.
- Reconcile ledger and outbox/inbox after restore before re-enabling advice.
- Restore cannot emit historical recommendations to production Telegram.
- A failure of OpenClaw is irrelevant because it is absent from core dependencies.

### التحقق والاختبارات

- Documented destructive exercise only in an isolated approved test environment.

**Evidence:** أضف دليلًا فعليًا داخل `docs/evidence/` واربطه بالحالة. لا تعني هذه القائمة أن الملفات أو الاختبارات موجودة الآن.
